## ข้อมูลที่เตรียม

- เพิ่มภาระงานบัญชีละ 16 รายการ: assignment, quiz, midterm, project มีทั้งงานเสร็จพร้อมคะแนน งานเสร็จยังไม่กรอกคะแนน และงานค้าง
- เก็บงาน/คะแนน/ประวัติจับเวลาเดิมของ user 6 ไว้ ไม่ลบ
- คะแนนสะสมจริงรวมต่อวิชา: user 6 = 60/70 และ 61/70; user 7 = 63/70 และ 60/70 เป้าหมาย A ทั้งสองวิชา ยังไม่ใส่คะแนนสอบปลายภาคจริง
- คะแนนแบบทดสอบแยกจากคะแนนเกรด: มีประวัติกลางภาคสองรอบต่อบัญชี ใช้คำถาม/ตัวเลือกจริงพร้อมผลรายพาร์ท รอบแรกและรอบถัดมา user 6 = 27%, 53%; user 7 = 28%, 48%
- Checkpoint ถัดไปของทั้งสองบัญชี: 3 สิงหาคม 2026 เวลา 08:00
- เพิ่มประวัติจับเวลาบัญชีละ 22 ครั้ง: user 6 ตัวอย่างอ่านตามช่วงที่วางไว้ ทั้งครบและไม่ครบเวลา; user 7 ตัวอย่างอ่านนอกช่วงที่วางไว้ ทั้งครบและไม่ครบเวลา พร้อมประวัติช่วงปลายเทอม
- แผนตัวอย่างบัญชีละ 5 สัปดาห์: 6, 13, 20, 27 กรกฎาคม ยืนยันแล้ว; 3–9 สิงหาคม รอยืนยัน (เพิ่มเวลาทบทวนคณิตศาสตร์ 30 นาที)
- แผนเหล่านี้เป็น mock baseline ระบุ rule_version=demo67-v1 ไม่ใช่ผลที่เพิ่งคำนวณจาก engine ส่วนคำแนะนำรอบที่ทำข้อสอบจริงระหว่างสาธิตจะมาจาก engine
- รีเซ็ตสถานะรับทราบ popup หลังกลางภาคแล้ว โดยยังไม่มีผลสอบปลายภาคที่ส่งแล้ว จึงพร้อมเริ่มแบบทดสอบปลายภาคครั้งแรก
- ยกเลิกสถานะข้อสอบทดลองเดิมของ user 6 และเปลี่ยนแผนเดิมเป็น superseded โดยเก็บรายละเอียดเดิมและสำรองไว้

คลังที่มีอยู่มีข้อสอบเฉพาะ Discrete Mathematics ทั้งกลางภาค/ปลายภาค วิชา Information Technology Fundamentals ไม่มีคลังข้อสอบ จึงไม่ได้สร้างข้อสอบเพิ่มในข้อมูลอาจารย์ การทำครบทุกวิชาในรอบสาธิตนี้หมายถึงวิชาที่มีข้อสอบเท่านั้น

## ข้อควรระวังก่อนเปิดบัญชี

1. เริ่มสาธิตที่ 3 สิงหาคมก่อนเปิดบัญชี แล้วเดินวันไปข้างหน้า ถ้าเปิดที่วันที่จริง 19 ตุลาคมก่อน ระบบสามารถยกเลิก checkpoint กลางภาคที่ค้างตามกฎได้
2. ต้องเปลี่ยนวันที่เครื่องที่รัน backend และ MySQL ให้ตรงกัน ไม่ใช่เปลี่ยนเฉพาะโทรศัพท์ เพราะโฟลวใช้ทั้งเวลาของ backend และฐานข้อมูล ใช้เขตเวลา Asia/Bangkok
3. หลังเปลี่ยนวันให้เปิดหน้าใหม่/รีโหลดแอป หาก token ใช้ไม่ได้หลังย้อนวัน ให้เข้าสู่ระบบใหม่
4. การย้อนเวลาไม่ได้คืนสถานะฐานข้อมูล: ข้อสอบที่ส่งแล้ว, checkpoint ที่ยกเลิก, popup ที่รับทราบ และเทอมที่จบแล้วจะยังคงสถานะนั้น อย่ากดจบเทอมจนกว่าจะถ่ายภาพครบ
5. ข้อมูลคะแนนและประวัติทั้งเทอมเป็น mock ที่เติมไว้ล่วงหน้า ไม่ใช่ระบบย้อนฐานข้อมูลตามวันจำลอง จึงอาจเห็นรายการที่อยู่หลังวันที่ตั้งเครื่องได้
6. รอบ midterm_2w / midterm_1w / final_2w / final_1w และข้อสอบปลายภาคครั้งแรกยังไม่ได้ทำ ต้องทำจริงในแต่ละช่วงเพื่อดูการเปลี่ยนแจ้งเตือนและการสร้างคำแนะนำ ไม่ได้เติมผลล่วงหน้าให้ข้ามขั้น
7. popup หลังกลางภาคที่รีเซ็ตจะเข้าเงื่อนไขตั้งแต่ 31 สิงหาคม และไม่แสดงในช่วง final_1w ที่เริ่ม 19 ตุลาคม การไม่ขึ้นที่วันที่ปัจจุบันจึงไม่ใช่รีเซ็ตไม่สำเร็จ
